# بيسان التعليمية — منصة تواصل المعلم والطالب

منصة Telegram WebApp لإدارة الصفوف والواجبات والتسليمات والبطاقات التحفيزية.
مبنية بمعمارية نظيفة (Clean Architecture) ومدفوعة بالأحداث، جاهزة للتوسّع من
مدرسة بفرع واحد إلى مجموعة مدارس متعددة الفروع دون إعادة تصميم.

## البنية

```
baysan/
├── apps/
│   ├── api/    NestJS — Clean Architecture (domain/application/infrastructure/presentation)
│   └── web/    Next.js 15 — Telegram WebApp (لوحتا المعلم والطالب)
├── packages/
│   └── shared/ أنواع وثوابت مشتركة (مصدر حقيقة واحد)
└── docker-compose.yml
```

## المبادئ المعمارية

- **Multi-tenant من اليوم الأول:** طبقة Organization/Branch — مدرسة بفرع واحد = مؤسسة بفرع واحد (نفس الكود).
- **RBAC كامل:** الأدوار السبعة معرّفة، الـMVP يستخدم TEACHER/STUDENT/BRANCH_ADMIN.
- **مدفوع بالأحداث:** `AssignmentCreated`, `SubmissionCreated`, `SubmissionGraded`, `RewardGranted` — المنتِج لا يعرف مستهلكيه (إشعارات/نقاط/تحليلات منفصلة).
- **منافذ (Ports) للمستقبل:** StoragePort / NotificationPort / CachePort / AI ports — واجهات فقط، تُبدَّل تطبيقاتها دون لمس منطق الأعمال.
- **سرعة قصوى + حد أدنى للتخزين:** الملفات لا تُخزَّن في القاعدة (المسار فقط)؛ الرفع/التنزيل عبر روابط موقّعة مباشرة بين المتصفح و Supabase — الخادم لا يمرّر بايتات.
- **ترقيم بالمؤشر (cursor)** لا offset — أداء ثابت مهما كبر الجدول.

## التشغيل السريع

```bash
# 1) المتطلبات: Node 20+, pnpm 9, Docker (اختياري)
pnpm install

# 2) الإعداد
cp .env.example .env
# املأ: TELEGRAM_BOT_TOKEN, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, JWT_SECRET

# 3) قاعدة البيانات
docker compose up -d db
pnpm --filter @baysan/api prisma:generate
pnpm --filter @baysan/api prisma:migrate

# 4) التشغيل
pnpm --filter @baysan/api start:dev   # المنفذ 4000
pnpm --filter @baysan/web dev         # المنفذ 3000
```

أو بالكامل عبر Docker:

```bash
docker compose up --build
```

- API + Swagger: http://localhost:4000/api/v1/docs
- WebApp: http://localhost:3000

## تدفّق العمل

1. المعلم ينشئ صفًا → يحصل على رمز مكوّن من 6 خانات.
2. الطالب يدخل الرمز في التطبيق → ينضمّ للصف.
3. المعلم ينشئ واجبًا وينشره → إشعار Telegram فوري لكل طلاب الصف.
4. الطالب يسلّم (نصًا و/أو ملفًا) → يمكن الاستبدال قبل الموعد مع حفظ التاريخ؛ التأخير يُكتشف تلقائيًا.
5. المعلم يصحّح ويكتب ملاحظة → إشعار للطالب + منح نقاط تلقائي عند الدرجة العالية.
6. المعلم يرسل بطاقة تحفيزية (نقاط مرافقة اختيارية) → تظهر في تبويب "بطاقاتي".
7. النقاط تُحسب من سجل شفّاف (ledger) — جاهز لعرضها لولي الأمر مستقبلًا.

## الحالة

- ✅ المرحلة 1 — الأساس: إعداد، مخطط، مصادقة Telegram، RBAC، منافذ، أحداث.
- ✅ المرحلة 2 — منطق الأعمال: صفوف، واجبات، تسليمات، بطاقات، رسائل، إشعارات، تحليلات.
- ✅ المرحلة 3 — الواجهة: هوية بيسان (بنفسجي×فيروزي)، لوحتا المعلم والطالب، تكامل Telegram.

كلا التطبيقين (API + Web) يُصرّفان بصفر أخطاء TypeScript.

## ملاحظة على التوليد

`prisma generate` و`prisma migrate` يحتاجان اتصالًا بـ`binaries.prisma.sh` لتنزيل المحرك.
شغّلهما في بيئتك المحلية بعد `pnpm install`.

## المكتبة العلمية (PhET) — مجّانية للجميع

- **خارج جدار الاشتراك تمامًا:** البحث وفتح المحاكيات متاحان لكل مستخدم مسجّل الدخول بلا أي فحص اشتراك. الخدمة المدفوعة هي إدارة الواجبات حول المحاكاة، لا المحاكاة نفسها.
- **بلا استضافة ولا تخزين محتوى:** نحتفظ بدليل روابط خفيف فقط (`src/lib/phet-catalog.ts`)؛ المحاكاة تُفتح في iframe مباشرةً من phet.colorado.edu.
- **تضمين آمن:** iframe بنسبة PhET الرسمية 834×504 مع `sandbox="allow-scripts allow-same-origin allow-popups"`.
- **تنويه إلزامي بالبنط العريض:** مكوّن `PhetAttribution` يظهر في كل مكان تُعرض فيه المحاكيات (المكتبة + داخل الواجب)، بنص كامل ورابط، وبلا استخدام شعار PhET.
